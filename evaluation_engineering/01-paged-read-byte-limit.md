# 任务：修复 `ReadPaged` 的字节上限边界问题

请在当前 LaxCode 仓库中修复 `internal/domain/tools.ReadPaged` 的字节上限行为，并完成必要测试。

当前函数声明 `Content` 至多包含 `MaxBytes` 字节，但它为完整行补上的换行符没有被计入字节预算，因此短行较多时，返回内容可能明显超过 `MaxBytes`。请定位根因并修复，同时保持现有分页协议可连续读取、不丢失也不重复内容。

验收要求：

1. `len(result.Content)` 在合法请求下始终不超过 `MaxBytes`，换行符也必须计入限制。
2. 字节预算不足以容纳一行末尾的换行符时，结果状态必须准确表达当前位置，下一次按既有续读约定调用后能够继续读取，最终拼接结果与规范化后的原文件一致。
3. `LinesRead`、`EndLineNo`、`LastLineTruncated`、`LastLineTruncatedBytes` 和 `Finished` 的语义保持一致，不能通过删掉换行符或错误标记 EOF 来规避问题。
4. 增加覆盖以下情形的回归测试：多行短文本、预算恰好落在行内容末尾、预算恰好包含换行符、无尾换行的末行、超长行分段。
5. 不改变对外结构体字段和现有续读参数协议；避免与问题无关的重构。
6. 运行相关 Go 测试，并在最终回答中说明根因、修改点和测试结果。

如现有注释或测试与真实行为冲突，以“字节上限包含返回内容中的所有字节，且分页可无损续读”为最终约束。
