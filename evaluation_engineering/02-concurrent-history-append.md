# 任务：保证会话历史并发追加的完整性

请改进当前 LaxCode 仓库中的会话历史持久化，使同一进程内多个 goroutine 同时向同一个 session 追加消息时，`history.jsonl` 仍然可靠，并补充能够稳定复现问题的测试。

重点检查 `internal/infrastructure/sessionrepo` 中历史追加路径。当前实现对文件执行并发打开和追加，但没有明确保证一次批量追加在并发情况下的完整性和批次连续性。

验收要求：

1. 多个 goroutine 并发向同一个 session 追加时，最终文件中的每一行都是完整、可解析的 JSON，消息不得丢失或重复。
2. 单次追加调用传入的多条消息在文件中必须保持原顺序并连续出现，不能被另一个 goroutine 的批次穿插。
3. 不同 session 的写入不应被一个全局大锁无谓串行化。
4. 保持现有 JSONL 格式、目录权限和文件权限，不改变领域层接口。
5. 锁或其他协调资源不能随着大量 session ID 持续使用而无界增长；说明采用的生命周期策略。
6. 添加并发回归测试。测试应检查消息总数、JSON 可解析性、每个批次内部的顺序和连续性，并可在 `go test -race` 下运行。
7. 避免依赖 `time.Sleep` 碰运气制造并发；使用同步机制让测试尽量确定。
8. 运行相关普通测试和 race 测试，并在最终回答中说明并发风险、实现取舍和验证结果。

请先阅读现有仓库实现和测试风格，再做最小范围修改；不要顺带调整无关模块。
